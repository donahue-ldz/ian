# 0269 · Moment User Control And Guardrails

## 问题 / 目标

Moment 增强生命感的同时，必须给用户明确控制权。用户应能降低惊喜强度、开启安静模式、减少动效，并且这些控制要被所有 Moment 遵守。

## 当前产品阶段

v0.1.x Life Feel / User Control。

## 产品范围

- 梳理 Moment 相关用户控制项。
- 提供最小设置入口，例如惊喜强度、安静模式、减少动效。
- 确保找回、追随、拖动、放下、idle、记忆回响都遵守控制项。
- 增加诊断状态展示，让验收能看出某个 Moment 被抑制的原因。

## 明确不做

- 不做复杂偏好系统。
- 不做插件级权限中心。
- 不做高敏来源授权。
- 不实现云同步。

## 用户体验

用户可以让 Ian 更活泼，也可以让它安静下来。Ian 的惊喜感不应牺牲用户控制。

## 架构约束

- 控制项进入 Rust Core policy，由 Core 决定 Moment 是否允许。
- React 设置面板只修改配置和展示状态。
- 所有 Moment 必须统一走 guardrail，而不是各自临时判断。

## 数据 / 协议变化

允许新增本地配置字段，例如 `moment_intensity`、`quiet_mode` 或等价字段。必须有默认值和兼容读取。

## 隐私与安全边界

设置项不涉及高敏数据。诊断状态不得暴露用户隐私或内部记忆原文。

## 验收标准

- [ ] 用户可以在设置中调整 Moment 强度或安静程度。
- [ ] DND / quiet mode 开启时，非必要 Moment 被抑制或降级。
- [ ] reduced motion 开启时，移动和特效强度降低。
- [ ] 每个 Moment 都通过统一 guardrail 判断。
- [ ] 诊断状态能解释被抑制原因，且不暴露隐私。

## 验证方式

- Rust policy 测试覆盖每个 Moment 的允许 / 抑制。
- 前端设置测试覆盖配置修改和状态显示。
- 真实 Tauri 桌面分别验证正常、安静、减少动效三种模式。
