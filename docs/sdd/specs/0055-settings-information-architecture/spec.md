# Spec: Settings Information Architecture

## 状态

草稿，待确认。

## 问题 / 目标

设置不应按内部模块和技术名词堆开关。0055 目标是按用户心智重组设置结构，让用户能快速理解“Ian 怎么陪我、什么时候打扰我、读取什么数据”。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 设置分组建议：性格、生活节奏、打扰、隐私、高级。
- 把技术项移入高级或隐私分组，并用中文短句解释。
- 默认展示少量高价值选项，折叠低频配置。
- 设置入口和设置面需要与 0051 的低干扰策略兼容。

## 明确不做什么

- 不做完整偏好系统重写。
- 不新增账号、云同步或插件配置。
- 不把所有内部 debug 开关暴露给用户。
- 不改变权限默认关闭原则。

## 用户体验

用户进入设置后，先看到与陪伴体验直接相关的选项，而不是 adapter、protocol、runtime 等内部概念。高级设置存在，但不会打断普通用户。

## 架构约束

- React 可以重组设置呈现，但持久化字段和 Rust 配置仍保持单一来源。
- 技术字段命名不直接暴露给主路径用户。
- 任何设置变更必须走既有 command / config 保存路径。

## 数据 / 协议变化

优先复用现有配置字段。可新增 UI grouping metadata，但不能成为行为状态源。

## 隐私与安全边界

隐私和权限设置必须始终可达，不能被隐藏到难以发现的位置。

## 验收标准

- [ ] 设置分组按“性格 / 生活 / 打扰 / 隐私 / 高级”或等价用户心智组织。
- [ ] 首屏设置不出现未经解释的 adapter、protocol、runtime 等技术词。
- [ ] 隐私和权限入口可在一屏内发现。
- [ ] 高级配置默认折叠或后置。
- [ ] 所有中文文案在窄宽度下不溢出。

## 验证方式

- 前端测试覆盖设置分组和配置保存。
- Browser smoke 截图：默认设置页、隐私页、高级页。
- 人工检查中文文案和响应式布局。
