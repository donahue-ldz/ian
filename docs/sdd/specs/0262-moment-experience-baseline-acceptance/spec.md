# 0262 · Moment Experience Baseline Acceptance

## 问题 / 目标

0252-0260 已经建立 Moment 能力和验收清单，但当前风险是“能力存在”不等于“桌面体验成立”。本 SDD 先做一次真实桌面体验基线验收，把 Ian 当前生命感问题客观记录下来，作为后续调参依据。

## 当前产品阶段

v0.1.x Life Feel / Moment 体验验收。

## 产品范围

- 按 `docs/sdd/moment-desktop-acceptance.md` 在真实 Tauri 桌面壳逐项验收。
- 记录找回、鼠标好奇、拖动、放下、idle 惊喜、记忆回响的实际表现。
- 输出问题分级清单，区分阻塞、明显体验问题、轻微调参项。
- 不直接修改产品行为。

## 明确不做

- 不新增 Moment。
- 不做浏览器替代验收。
- 不以主观“好看/不好看”作为唯一结论，必须落到可复现现象。

## 用户体验

验收完成后，其他会话能明确知道 Ian 哪些地方“不灵动”的具体表现，例如位置跳动、拖不动、移动太机械、气泡遮挡、惊喜频率不合适。

## 架构约束

- 桌面可见能力必须在真实 Tauri 桌面壳验证。
- 验收结果只记录低敏观察，不采集屏幕内容和隐私文本。
- 不绕过 Rust Core / `IanAction` 架构边界。

## 数据 / 协议变化

不需要协议变化。

## 隐私与安全边界

不得记录用户屏幕内容、文件名、聊天内容、剪贴板、代码正文或终端完整输出。

## 验收标准

- [ ] 启动真实 Tauri 桌面壳并记录启动命令和结果。
- [ ] 按清单覆盖至少 6 类 Moment：找回、鼠标好奇、拖动抱起、放下安顿、idle 惊喜、记忆回响。
- [ ] 每类 Moment 记录触发步骤、预期表现、实际表现、失败判定。
- [ ] 输出按优先级排序的问题清单。
- [ ] 对无法复现或无法验收的项记录原因和剩余风险。

## 验证方式

- 真实 Tauri 桌面人工验收。
- 必要时补充 `npm run desktop:test`、`npm run desktop:typecheck` 作为回归基线。
- 更新 `verification.md`。
