# Spec: Privacy Permission Copywriting

## 状态

已实现，待用户验收。

## 问题 / 目标

Ian 的隐私和权限说明需要让用户一眼理解，而不是依赖抽象承诺。0056 目标是建立中文优先的权限文案规则，明确每项能力“会读取什么、不会读取什么、如何关闭”。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 为敏感能力补充统一文案结构：会读取、不会读取、可随时关闭。
- 覆盖 Git、build/test 摘要、键盘节奏、活动应用类别和 dialogue provider。
- 文案中文优先，短句优先，避免法律化长段落。
- 权限状态变化后给出明确反馈。

## 明确不做什么

- 不写完整法律隐私政策。
- 不新增云端账号或远程同步说明。
- 不模糊承诺“绝对安全”。
- 不隐藏敏感能力的关闭入口。

## 用户体验

用户看到权限开关时，能清楚知道 Ian 是否会读取内容、读取到什么粒度、不会碰什么敏感信息，并知道随时可以关掉。

## 架构约束

- 文案必须和 Security Gate 实际能力一致。
- 不能在 UI 文案承诺 Core 没有实现的限制。
- 权限说明可以复用配置 schema 或 capability metadata，但不能绕过 Rust 权限判断。

## 数据 / 协议变化

可新增 capability description metadata。若新增，必须能表达中文短文案和敏感非目标。

## 隐私与安全边界

每项能力必须列出不会读取的敏感内容，例如代码正文、diff、终端全文、按键内容、窗口标题、URL、屏幕文字。

## 验收标准

- [ ] 每项敏感能力都有“会读取 / 不会读取 / 可关闭”说明。
- [ ] 中文文案默认优先展示。
- [ ] 文案与实际权限 gate 行为一致。
- [ ] 关闭权限后对应事件被拒绝或停止采集。
- [ ] 不出现夸大、模糊或无法验证的隐私承诺。

## 验证方式

- Security tests 覆盖关闭后拒绝。
- 前端测试覆盖文案存在和开关状态。
- 人工审查文案与实现一致性。
