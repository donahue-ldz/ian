# 0263 · Moment Debug Trigger Surface

## 问题 / 目标

Moment 有低频和冷却策略，导致体验调参时很难稳定复现。本 SDD 增加仅用于开发 / 诊断的 Moment 触发入口，让桌面验收可以确定性触发每个 Moment。

## 当前产品阶段

v0.1.x Life Feel / Desktop QA。

## 产品范围

- 提供开发或诊断入口，手动触发已存在的 Moment。
- 覆盖找回入场、鼠标好奇、拖动抱起、放下安顿、idle 惊喜、记忆回响。
- 触发入口必须清楚标识为诊断能力，不作为普通用户主流程。
- 保持 Rust Core 决策边界，触发请求进入 Core 后仍由 Core 产出 `IanAction`。

## 明确不做

- 不新增正式用户功能。
- 不绕过冷却策略成为线上随机行为。
- 不读取任何高敏输入。
- 不暴露内部隐私数据。

## 用户体验

开发和验收时可以快速点选某个 Moment，立即观察 Ian 在真实桌面上的动作、气泡、移动和效果，从而高效调参。

## 架构约束

- 诊断触发必须通过 `IanEvent` 或等价 Core 入口进入 Rust Core。
- React 只能发送诊断触发和执行返回的 `IanAction`。
- 诊断入口需要能在生产体验中隐藏或明确降级。

## 数据 / 协议变化

允许新增低敏诊断事件或命令，但必须由 Rust 类型作为协议源头。

## 隐私与安全边界

诊断入口不得展示或导出 memory 原文、用户输入原文、文件内容、剪贴板、屏幕 OCR 或终端输出。

## 验收标准

- [ ] 真实桌面端存在可访问的诊断入口或等价触发方法。
- [ ] 每个已实现 Moment 都能被确定性触发一次。
- [ ] 触发后 React 执行 Rust Core 返回的 `IanAction`，不是前端直接伪造行为。
- [ ] 诊断入口不泄露高敏数据。
- [ ] 生产默认体验不会频繁暴露该入口。

## 验证方式

- 单元测试覆盖诊断事件到 Moment action 的路径。
- 前端测试覆盖入口渲染和触发调用。
- 真实 Tauri 桌面逐项手动触发并记录结果。
