# Spec: Playful Trigger Rules

## 状态

草稿，待确认。

## 问题 / 目标

高能彩蛋需要触发规则，否则要么不出现，要么太吵。0065 目标是定义用户触发、自发触发和组合触发的概率、冷却、取消条件。

## 产品范围

- 用户触发：双击、连续点击、拖拽后放下、唤醒后短时间互动。
- 自发触发：长时间 idle 后低概率 playful burst。
- 组合触发：亲近互动累积后短时提高撒娇或 zoomies 概率。
- 每类触发都有冷却和日内上限。

## 明确不做什么

- 不按用户代码、屏幕内容或键盘文本触发。
- 不在安静模式中自发触发。
- 不在设置、输入、拖拽中触发。
- 不用高能彩蛋替代正常点击反馈。

## 用户体验

Ian 的高能行为像偶尔冒出来的惊喜：用户能通过互动更容易触发，但不会频繁到烦。

## 架构约束

- 触发规则由 Rust Core policy 管理。
- 触发结果必须输出明确 action sequence。
- 触发规则需要能被本地诊断解释。

## 数据 / 协议变化

可新增 internal trigger reason，用于日志和测试，例如 `user_burst`、`idle_surprise`、`affection_overflow`。

## 隐私与安全边界

触发只基于本地 Ian 事件和本地配置，不读取外部内容。

## 验收标准

- [ ] 用户连续互动可提高 playful 触发概率但受冷却限制。
- [ ] 长时间 idle 可低概率触发，但 quiet / off 时不会触发。
- [ ] 拖拽、输入、设置打开时不会启动高能行为。
- [ ] 每次触发有 reason 便于诊断。
- [ ] 测试覆盖触发、冷却、取消和上限。

## 验证方式

- Rust policy tests。
- 本地诊断日志检查。
- Browser smoke：连续互动和长 idle 场景。
