# 0279 · Desktop Life Feel Acceptance V2

## 问题 / 目标

生命感不能只靠单元测试确认。本 SDD 建立生命感二阶段桌面验收标准，用可复现步骤检查 Ian 是否比之前更有趣、更有惊喜、更像活在桌面上。

## 当前产品阶段

v0.1.x Life Feel / Acceptance。

## 产品范围

- 定义生命感二阶段验收清单。
- 覆盖 Life Drive、Micro Story、Motion Feel、追鼠标、找回、拖动、放下、idle 私生活、重复避免。
- 要求真实 Tauri 桌面验收。
- 记录主观体验观察，但必须对应客观触发和现象。

## 明确不做

- 不用浏览器替代桌面验收。
- 不要求完全自动化所有视觉体验。
- 不采集屏幕内容或用户隐私。
- 不把“感觉好”作为没有证据的通过标准。

## 用户体验

验收后应能回答：Ian 是否有短故事、是否有身体感、是否会偶尔做自己的事、是否避免机械重复、是否仍然可控不打扰。

## 架构约束

- 验收必须确认行为仍由 Rust Core 决策。
- 验收必须确认 React 只执行 `IanAction`。
- 验收必须覆盖 DND、quiet、reduced motion 的降级。

## 数据 / 协议变化

不需要协议变化。可以新增文档和验收测试。

## 隐私与安全边界

验收记录不得包含屏幕内容、文件内容、剪贴板、私聊、代码正文或终端完整输出。

## 验收标准

- [ ] 清单覆盖 0270-0278 的全部生命感二阶段能力。
- [ ] 每项都有触发方法、预期表现、失败判定。
- [ ] 至少执行一次真实 Tauri 桌面完整验收。
- [ ] 记录 DND / quiet / reduced motion 下的降级结果。
- [ ] 输出剩余体验问题和下一轮优先级。

## 验证方式

- 文档自检。
- `rg` 检查清单覆盖 0270-0278。
- 真实 Tauri 桌面完整验收并更新 `verification.md`。
