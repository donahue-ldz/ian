# Spec: Touch And Affection Language

## 状态

已实现，待用户验收。

## 问题 / 目标

点击、连点、拖拽和双击应形成一致的触摸语言。0053 目标是让用户能通过简单动作感到 Ian 有反馈、有边界、有亲近感，但不出现数值化养成或刷屏。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 定义单击、短时间连点、拖拽、双击的反应矩阵。
- 为触摸反应增加冷却和去重，避免连续弹气泡。
- 连续打扰时 Ian 可以温和表达“有点晕”或短暂停顿。
- 触摸反馈优先表现为动作、表情、短句，而不是分数变化。

## 明确不做什么

- 不显示 Mood / Bond 数值。
- 不做复杂抚摸识别。
- 不做惩罚系统。
- 不引入全局鼠标监听。

## 用户体验

用户轻点 Ian，会得到亲近回应；双击会触发已有惊喜动作；拖拽时 Ian 感觉被抱起或移动；连续打扰时 Ian 不生硬报错，而是温和降频。

## 架构约束

- 触摸输入进入 Rust Core 时应表达为 `IanEvent`。
- Core 决定触摸反应和冷却，React 只执行 `IanAction`。
- React 的 drag 视觉态可以局部处理，但不能绕过行为优先级。

## 数据 / 协议变化

可扩展 interaction event reason：`click`、`double_click`、`drag_start`、`drag_end`、`rapid_click`。具体命名遵循现有 Rust 类型。

## 隐私与安全边界

只处理 Ian 窗口内的鼠标交互，不采集全局鼠标轨迹。

## 验收标准

- [ ] 单击、双击、拖拽、连点有可区分的动作或短句。
- [ ] 连续点击不会无限叠加气泡或动作队列。
- [ ] 拖拽期间不会触发自主游走、睡眠或位置抢夺。
- [ ] 触摸反馈不显示 Mood / Bond 数字。
- [ ] 反应矩阵记录在代码或资源配置中，便于后续扩展。

## 验证方式

- Rust behavior tests 覆盖触摸事件优先级和冷却。
- 前端测试覆盖 drag 状态和事件发送。
- Browser smoke 覆盖单击、双击、拖拽、连续点击。
