# 0083 决策记录

## 2026-05-21

- 使用新的 `0083-click-triggered-pointer-chase`，因为仓库中已经存在多个 `0080-0082` 目录，避免覆盖其他会话内容。
- 点击后追逐不新增 Rust 协议事件，复用 `mouse.chase_candidate`，保持 Rust Core 作为行为大脑。
- 随机逻辑只决定是否发送一次候选坐标，不决定 Ian 是否移动。
- 浏览器预览不读取桌面鼠标坐标。

## 2026-05-21 调参

- 为了让真实桌面体验更容易观察，点击后的候选触发率从 25% 临时调整为 100%。
- 100% 只表示每次桌面点击都会发送一次 `mouse.chase_candidate`；是否移动仍由 Rust Core 的距离、冷却、安静模式、拖动和输入规则决定。

## 2026-05-21 鼠标离开触发

- 排查发现点击瞬间采样鼠标坐标时，鼠标仍在 Ian 身上，容易被 0080 的距离门槛拦截，或者产生过小移动，真实体验上看起来像没有触发。
- 改为点击只布防，等鼠标从 Ian 身上离开时再读取当前桌面鼠标坐标并发送 `mouse.chase_candidate`。
- 这样保持 Rust Core 继续作为行为判定方，同时让体验验证更接近“鼠标移开，它追上来”。

## 2026-05-21 兜底触发

- 继续排查后发现 `pointerleave` 依赖 `.ian-click-target` 的透明命中区，用户从视觉宠物移开时可能仍在 192x192 按钮区域内，导致没有触发离开事件。
- 增加点击后 450ms 的短延迟兜底采样；如果 `pointerleave` 先触发，则取消兜底，避免重复候选。
- 兜底仍只发送 `mouse.chase_candidate`，实际是否移动仍由 Rust Core 判定。
