# Spec: Movement Personality Tuning

## 状态

已实现，待用户验收。

## 问题 / 目标

Ian 的移动不能只是随机位移。0054 目标是按性格和状态调整移动频率、路径、停顿和动作曲线，让 Ian 的行动看起来有意图且不过度打扰。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 定义 quiet、normal、lively 三档移动倾向。
- 优先使用呼吸、眨眼、姿态变化等微动作表达存在感。
- 自主移动需要有最大频率、最短间隔和屏幕边界约束。
- 不同状态下移动应与休息、输入、拖拽、忙碌策略兼容。

## 明确不做什么

- 不做复杂路径规划。
- 不做窗口感知躲避。
- 不做物理引擎。
- 不按用户代码内容改变移动。

## 用户体验

Ian 大部分时间安静存在，偶尔换位置或跑动时像是自己想动，而不是随机乱跳。用户在输入、拖拽或忙碌时，Ian 明显更克制。

## 架构约束

- 移动决策属于 Rust Core behavior policy。
- React 负责动画播放、插值和边界呈现，不自行决定何时自主移动。
- 移动参数应可由配置或资源包覆盖，但默认值必须可用。

## 数据 / 协议变化

可新增 movement profile 配置：频率、最短间隔、最大距离、曲线类型。协议字段以 Rust 类型为准。

## 隐私与安全边界

不读取屏幕内容、窗口标题或其他应用状态。若需要活动应用类别，必须复用已授权的粗粒度 category。

## 验收标准

- [ ] quiet、normal、lively 三档移动频率可区分。
- [ ] 自主移动不会在输入聚焦、拖拽、睡眠中触发。
- [ ] 移动不会越界或遮挡自身气泡。
- [ ] 同一状态下短时间内不会频繁重复跑动。
- [ ] 微动作可以在不移动位置时表达生命感。

## 验证方式

- Rust behavior tests 覆盖移动调度和状态互斥。
- 前端测试覆盖移动 action 执行和边界。
- 长时间 smoke 观察 5 分钟 idle 行为。
