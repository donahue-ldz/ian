# Spec: Settings Surface

## 状态

已实现，已验证。

## 问题 / 目标

P0 已有基础行为，但用户缺少最小控制面。0007 目标是提供克制的设置入口，让用户能调整 Ian 的基础存在感，同时不把产品变成复杂工具面板。

## 当前产品阶段

v0.1.x Product Iteration。

## 产品范围

- 一个轻量设置面板或气泡内设置入口。
- 可调整基础行为强度、是否显示气泡输入、资源包显示信息。
- 设置保存在本地配置。

## 明确不做什么

- 不做账号、云同步、插件市场。
- 不做复杂资源包管理。
- 不做 BYOM 密钥配置。
- 不展示 Mood/Bond 数值。

## 用户体验

用户能打开一个小设置面，选择“安静 / 正常 / 活泼”之类的行为模式，并在重启后保持。

## 架构约束

- 设置项必须映射到 Rust Core 可理解的配置或状态。
- React 负责表单渲染，不直接决定长期行为。
- 所有设置修改经 Tauri command 进入 Rust。

## 数据 / 协议变化

可新增 `BehaviorMode` 保存和同步能力；如已有类型，优先复用。

## 隐私与安全边界

设置只保存在本机，不采集环境信息。

## 验收标准

- [ ] 用户可打开和关闭设置面板。
- [ ] 用户可选择行为模式，并通过 Rust command 保存。
- [ ] 重启后行为模式恢复。
- [ ] 设置 UI 不展示未来阶段能力入口。
- [ ] 前端测试覆盖设置状态变更。

## 验证方式

- 前端组件/状态测试。
- Rust config 测试。
- Playwright 验证设置打开、修改、重启恢复。
