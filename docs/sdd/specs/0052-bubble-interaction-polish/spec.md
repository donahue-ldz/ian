# Spec: Bubble Interaction Polish

## 状态

草稿，待确认。

## 问题 / 目标

Ian 的气泡应像生命反馈，而不是聊天应用窗口。0052 目标是统一气泡长度、出现时机、输入态和消退规则，让交互短、轻、可预期。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 限制默认气泡文案长度，优先一到两行短句。
- 区分只读反馈气泡和用户主动输入气泡。
- 用户输入激活时，暂停会打断输入的自主移动、休息或气泡切换。
- 气泡消退、替换和重复出现需要有冷却规则。

## 明确不做什么

- 不做完整聊天记录。
- 不做多轮长对话窗口。
- 不新增外部大模型能力。
- 不把气泡变成通知中心。

## 用户体验

用户点击或唤起 Ian 时，气泡给出短促回应。用户主动输入时，Ian 安静等待，不乱跑、不抢话、不反复弹出新内容。

## 架构约束

- 气泡显示原因来自 `IanAction` 或 React 输入态，不在 React 中推导完整行为策略。
- React 可以维护局部输入焦点状态，但需要通过事件或状态告知 Core，避免 Core 继续调度冲突动作。
- 文案资源应归入资源包或 dialogue boundary，避免散落硬编码。

## 数据 / 协议变化

可新增轻量输入态事件，例如 `BubbleInputFocused` / `BubbleInputBlurred`。若已有等价事件，优先复用。

## 隐私与安全边界

输入内容只按现有 Demo Dialogue 或本地 dialogue provider 边界处理，不新增持久化或外发。

## 验收标准

- [ ] 默认反馈气泡不超过两行，长文本会被改写或折叠。
- [ ] 输入框只有用户主动触发后才展开。
- [ ] 输入聚焦时 Ian 不触发自主游走、睡眠或覆盖性气泡。
- [ ] 重复点击不会造成气泡刷屏。
- [ ] 气泡退出动画不遮挡 Ian 的关键动作。

## 验证方式

- 前端测试覆盖输入聚焦、失焦、气泡替换和冷却。
- Browser smoke 覆盖点击、输入、等待消退。
- 人工检查中文文案换行和移动端宽度。
