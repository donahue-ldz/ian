# 0264 · Find Ian Return And Beacon Tuning

## 问题 / 目标

用户有时在桌面上找不到 Ian。找回能力已经存在，但需要把“快速定位 / 唤醒 Ian”的体验调到可靠、明显、不过度打扰。

## 当前产品阶段

v0.1.x Life Feel / Desktop Control。

## 产品范围

- 优化找回 Ian 的入场位置、移动路径、视觉提示和气泡反馈。
- 确保 Ian 被找回后落在当前可见屏幕的安全区域。
- 找回过程要有短暂生命感，例如探头、挥手、轻跳或短气泡。
- 使用 0263 的诊断触发入口辅助验收。

## 明确不做

- 不做全局键盘监听扩展。
- 不读取活动窗口内容。
- 不做复杂窗口感知或跨应用追踪。
- 不把找回做成通知系统。

## 用户体验

用户触发找回后，Ian 应该快速出现在可见位置，有轻微入场反馈，让用户知道“它回来了”，但不会遮挡主要工作区太久。

## 架构约束

- 找回触发进入 Rust Core 后产出 `IanAction`。
- React 负责移动、动画、气泡执行，不决定找回策略。
- 位置计算必须遵守 safe zone 和多屏边界。

## 数据 / 协议变化

尽量复用现有找回事件和移动 action；仅在现有协议无法表达入场反馈时新增动作。

## 隐私与安全边界

只使用屏幕几何和 Ian 自身窗口状态，不读取屏幕内容。

## 验收标准

- [ ] Ian 不可见或偏离安全区时，触发找回后回到当前可见屏幕安全区域。
- [ ] 找回动作包含短入场反馈，且持续时间可控。
- [ ] 找回过程中不会跳到屏幕外、被菜单栏遮挡或落在不可拖动区域。
- [ ] 连续触发找回不会导致动画堆积或位置抖动。
- [ ] reduced motion 开启时找回反馈降级为低动效。

## 验证方式

- Rust 位置策略测试。
- 前端移动 / 动画执行测试。
- 真实 Tauri 桌面在单屏和可用多屏环境验收。
