# Spec: Cute Affection Reaction Pack

## 状态

草稿，待确认。

## 问题 / 目标

现有撒娇反馈只有少量短句和 happy 动画，不够“卖萌”。0064 目标是建立可扩展的 cute reaction pack，让 Ian 在亲近互动中有更丰富的短句、动作和表情组合。

## 产品范围

- 增加中文优先短句池：贴贴、开心、害羞、想被摸、被点多了的小抗议。
- 增加反应类型：短句、happy、靠近、小退、转圈、蹭一下等。
- 反应有冷却和去重，避免连续刷同一句。
- 反应包可由资源包或 dialogue boundary 扩展。

## 明确不做什么

- 不写长对话。
- 不展示亲密度数字。
- 不做成人化或暧昧化文案。
- 不依赖云端模型生成卖萌语句。

## 用户体验

用户点击、拖动、唤醒 Ian 时，它会给出短小、可爱、有变化的回应，像在撒娇而不是执行命令。

## 架构约束

- 反应选择由 Rust Core 或 dialogue policy 决定。
- React 只播放动作和显示短句。
- 文案应集中管理，避免散落硬编码。

## 数据 / 协议变化

可新增 reaction pack 配置或资源 manifest 字段。短句需要支持 mood、duration、cooldown key。

## 隐私与安全边界

反应只基于本地互动和 Ian 状态，不读取用户文本、代码或应用内容。

## 验收标准

- [ ] 至少有 12 条中文短句覆盖不同亲近场景。
- [ ] 同一句不会在短时间内连续重复。
- [ ] 连续点击有可爱反馈但不刷屏。
- [ ] 反应包不暴露 Mood / Bond 数字。
- [ ] 文案符合 Ian 不是 AI 助手的定位。

## 验证方式

- Rust behavior / dialogue tests。
- 文案审查。
- Browser smoke：连续互动观察短句变化。
