# Spec: Product Feel Acceptance Suite

## 状态

草稿，待确认。

## 问题 / 目标

产品体验不能只靠单项功能测试。0060 目标是建立 Product Feel 验收套件，用固定场景验证 Ian 是否仍然像一个本地桌面生命，而不是工具、通知中心或聊天窗口。

## 当前产品阶段

Product Feel Acceptance。

## 产品范围

- 建立第一眼 30 秒验收：默认桌面存在、首屏控件、气泡、动作。
- 建立 5 分钟陪伴验收：idle、微动作、休息、低打扰。
- 建立核心交互验收：单击、双击、拖拽、输入、设置。
- 建立隐私和 Developer Rhythm 渐进暴露验收。
- 记录截图、命令和人工结论。

## 明确不做什么

- 不替代单个 SDD 的单元测试。
- 不做全量端到端自动化平台。
- 不把主观体验写成无法执行的空泛评价。
- 不验收 0050 以前已经通过的历史范围，除非本批改动影响到它。

## 用户体验

验收者可以按一份清单快速判断：Ian 是否安静、可爱、可控、隐私边界清楚，并且不会在第一眼暴露过多开发工具属性。

## 架构约束

- 验收套件应覆盖 Rust 行为、React 呈现和 Tauri 桌面 smoke。
- 自动化能覆盖的部分自动化，视觉和感受部分保留截图和人工记录。
- 不能为了通过验收把策略写死在 React UI。

## 数据 / 协议变化

不新增产品协议。可新增测试 fixtures、smoke scripts 或验收文档。

## 隐私与安全边界

验收必须覆盖默认未授权状态、权限关闭、权限说明和 Developer Rhythm 未开启状态。

## 验收标准

- [ ] 第一眼 30 秒内默认画面不显著工具化。
- [ ] 5 分钟 idle 中 Ian 没有过度移动、刷屏或卡死。
- [ ] 单击、双击、拖拽、输入和设置路径都可完成。
- [ ] 隐私说明能明确解释会读取和不会读取的内容。
- [ ] Developer Rhythm 默认不抢占主体验，但可从设置路径开启。
- [ ] 验收结果记录命令、截图和人工结论。

## 验证方式

- Rust behavior / security tests。
- `npm run desktop:test` 和 `npm run desktop:typecheck`。
- Tauri / Browser smoke 截图。
- 人工 Product Feel checklist。
