# Spec: Desktop Presence Chrome Reduction

## 状态

已实现，待用户验收。

## 问题 / 目标

Ian 的默认桌面存在应先被感知为一个陪伴对象，而不是一个悬浮工具。0051 目标是降低首屏工具感和控件感，让用户第一眼主要看到 Ian 本体、动作和必要气泡。

## 当前产品阶段

Product Feel 体验优化。

## 产品范围

- 收敛默认可见的设置入口、调试入口和技术状态文字。
- 保留设置可达性，但改为低干扰入口，例如小图标、右键菜单或长按入口。
- 检查透明窗口、边框、阴影和气泡层级，避免出现卡片式工具面板感。
- 保证首屏在桌面背景上不显得突兀、遮挡或像通知组件。

## 明确不做什么

- 不重做整体视觉品牌。
- 不新增皮肤市场或主题系统。
- 不删除设置能力，只调整默认暴露方式。
- 不引入 Developer Rhythm 的新功能。

## 用户体验

用户启动 Ian 后，第一眼应该看到一个安静待在桌面的 Ian。设置入口存在但不抢眼，用户需要时能找到，不需要时不会一直提醒自己这是一个工具。

## 架构约束

- React 可以调整呈现和入口，但不能把行为策略写进 UI。
- 设置入口触发的状态仍通过既有 command / event 路径进入 Rust Core 或配置层。
- 不绕过已存在的权限、配置和持久化边界。

## 数据 / 协议变化

优先不新增协议字段。若需要记录入口偏好，只允许新增本地 UI preference，不影响 Ian 行为状态。

## 隐私与安全边界

不新增外部数据读取。设置入口隐藏不能影响用户关闭权限和查看隐私信息。

## 验收标准

- [ ] 默认启动后的主画面没有醒目的“设置”文字按钮或调试文本。
- [ ] 设置仍可通过至少一种清晰方式进入，并支持键鼠操作。
- [ ] Ian 本体、气泡和设置入口不互相遮挡。
- [ ] 透明窗口在浅色和深色桌面背景上都可辨认。
- [ ] 无障碍标签或 tooltip 能说明低干扰入口的作用。

## 验证方式

- Browser / Tauri smoke 截图：默认态、hover 态、打开设置态。
- 前端测试覆盖设置入口可达。
- 人工检查浅色、深色背景下的视觉层级。
